# Code peek Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ctrl+click a file path in an agent's terminal on the Agent surface to unfold a read-only card under that line (Preview for markdown, Source, Diff vs HEAD), with Open in Code (Enter) and close (Esc, or Ctrl+click again).

**Architecture:** A pure detector finds file paths in a terminal row; `TermWrap` registers an xterm link provider for them that is live only while a handler is attached, and reports Ctrl-hover and Ctrl+click. The Agent surface attaches that handler through a React context, so other terminals are unchanged. One global peek atom holds the open card; a loader reads the file, its HEAD copy and its repository root over existing RPCs; a host in `TerminalView` pins the card to an xterm marker on the clicked line and renders it with `CodeEditor`, `Markdown` and the Monaco diff viewer directly, never through the Code surface's atoms.

**Tech Stack:** React 19, jotai, xterm.js 6 (link provider, markers, decorations), Monaco, Go (`pkg/gitinfo`), vitest, CDP scenarios.

## Decisions beyond the design (and why)

1. **The peek exists only where the Agent surface provides it.** `agentsurface.tsx` wraps each `CockpitFocusPane` in a `CodePeekContext` carrying the `AgentsViewModel` and the agent's `transcriptPath`. `TerminalView` renders the peek host only when that context is present, and `TermWrap` returns no file links until a handler is attached. Why: the goal scopes the feature to the Agent surface, and the generic terminal must not grow underlines that do nothing.
2. **Path detection is syntactic, with no stat on hover.** A candidate is a token with a `/` or `\`, or a bare `name.ext` with an extension of 2+ characters. It may carry a `:line[:col]` suffix, and wrapping quotes, backticks, parentheses or brackets and trailing `.,:;` are trimmed. Any `scheme://` span is excluded, so URLs stay with `WebLinksAddon`. Only a single buffer row is scanned, so a path wrapped across rows is not linked. Why: stat-per-hover adds an RPC on every mouse move for little gain, and the card already has a Missing state for a false positive.
3. **Underline only while the modifier is held.** The link's `decorations` start as `{underline:false, pointerCursor:false}` and flip to true while Ctrl is held over it (Cmd on macOS, mirroring the existing web-link rule). Ctrl pressed or released during the hover counts too. While it is held, an xterm decoration recolors the link's cells with `--color-accent-soft`, read from the document at hover time so themes apply. The hint is a small pill below the line at the pointer's x that reads "Ctrl + click to peek" (modifier per platform). It shows immediately, not after the web-link tooltip's 600 ms delay. Why: the Trigger board shows a colored underline and a hint only under Ctrl, and an always-on underline would mark every path the agent prints.
4. **Paths resolve against `resolveCwd(transcriptPath, blockId)` at click time** (block meta `cmd:cwd`, then the transcript). Absolute paths (drive, UNC, POSIX) are used as-is. A relative path with no cwd, or a `~`-prefixed path or cwd, opens the card in a "no working directory" state. Why: this reuses the one cwd resolver the rail and Files surface use, and the frontend has no home directory to expand `~` against.
5. **Repository root and repo-relative path come from git, not path arithmetic.** `gitinfo.FileAtRef` already runs `rev-parse` in the file's directory. It now also returns `--show-toplevel` and `--show-prefix`, so `rel = prefix + basename` and `projectPath = root` feed Open in Code. Why: comparing case and separator style on Windows (and through junctioned worktrees) is where string math goes wrong, and git already knows the answer in the same call.
6. **The diff stat comes from git numstat**, via `GitChangesCommand({cwd: root})` and `parseGitChanges`, looked up by `rel`. When the file has a change entry, its `adds`/`dels` are the stat, and a file absent at HEAD also gets the "new file" label. An untracked file has no numstat, so if it is absent at HEAD and its entry has no adds, the stat falls back to `+<line count>`. A tracked file with no entry reads "no changes". A non-repo file shows no stat. Why: it is the same source as the details rail's "Files touched" numbers, which the design shows matching (+15 in both).
7. **Mode buttons are disabled with a reason, never hidden** (the Code sidebar's precedent). Preview is disabled for a non-markdown file ("Preview is for markdown files"), and the card opens on Source. Diff is disabled outside a git repository (`NOT_TRACKED`). All three are disabled in the loading, missing, binary, too-large, error and no-cwd states. Markdown opens on Preview. The size gate and binary test reuse `classifyFile`, `hasNulByte` and `MAX_VIEW_BYTES` from `codeclassify.ts`. Diff renders the existing `MonacoDiffViewer` inline (`renderSideBySide:false`), with original `""` for a file new since HEAD under a "New file, not in HEAD" label. Source is a read-only `CodeEditor` that reveals the `:line` suffix. Editor model paths are prefixed `peek/`, so they never collide with the Code surface's kept models.
8. **The card is anchored to an xterm marker but rendered outside xterm's DOM.** A one-row decoration on the marker paints the line band (`bg-accentbg`), and the card is an absolutely positioned sibling in `TerminalView`'s relative root. It is placed from `marker.line - buffer.viewportY` and the cell height, and recomputed on the terminal's `onRender`/`onScroll`/`onResize`. It hides while its line is out of the viewport and closes when the marker is disposed (scrollback trimmed or cleared). Why: inside `.xterm-screen` the card would inherit xterm's cursor, selection and mouse handlers, and its wheel would scroll the terminal.
9. **Above or below is decided when the card opens, and again on resize, never on scroll.** It opens below when the room under the line fits the 400 px preferred height or beats the room above, and above otherwise. Its height is clamped to the chosen side's room, with a 160 px floor where the room allows. Horizontally it starts 4 cells in from the line's left and stops 24 px short of the terminal's right edge. Why: a card that flips while output streams is unreadable, and these measures match Main (830 px wide in an 892 px pane).
10. **One card at a time, in a global atom.** Ctrl+click on the same anchor (same block, buffer line and start column) closes the card. Ctrl+click on any other path, in this terminal or another, moves it. A load superseded by a newer click writes nothing. Opening focuses the card. Esc, the close button and the toggle-close return focus to that terminal's xterm. Open in Code closes the card after the landing succeeds. Why: the goal says one card that moves, and focus has to go somewhere the user can type.
11. **Enter and Esc are registry bindings gated on focus inside the card.** `codepeek:open` (Enter) and `codepeek:close` (Escape) live in `buildAgentBindings` and fire only while `codePeekFocusedAtom` is true, editable or not, because Monaco's textarea counts as editable. Every other Agent Escape binding gains `!codePeekFocused`. Why: Esc in the terminal interrupts the agent, so it must reach the agent unless the user is in the card. Bindings have one home (`bindings.ts`), and `shelltask:back` is the precedent.
12. **Open in Code goes through `openTarget`, with a new `code` target kind:** `{kind:"code"; projectPath; rel; line?}`. Its load stats the file (a missing file is reported as unavailable), then calls the existing `openInCode`. It is not peekable in the avatar popup. For a non-repo file, `projectPath` is the file's directory, since Code browses plain directories. "Opens the file in Code at the same line" (PeekPanel) means the `:line` suffix of the clicked path. The Source view reveals that line, and Open in Code lands on it. It is not the line the user scrolled to inside the card, which is not tracked. A path with no suffix opens Code at the top. Why: AGENTS.md routes every cross-surface open through the one router, and `openInCode` already does the Code-side work.
13. **Header path:** the repo-relative path inside a repository, else the absolute path, with the absolute path as its `title`.

## Global Constraints

- Colors only from `@theme` tokens in `frontend/tailwindsetup.css`. No raw hex or rgba in components and no new tokens. The design's colors map to existing tokens: `background`, `border`, `edge-mid`, `edge-strong`, `surface-raised`, `surface-code`, `accent`, `accent-soft`, `accentbg`, `muted`, `secondary`, `ink-faint`, `success`, `error`.
- Copy, verbatim from the design: header label "File"; "Read-only"; buttons "Preview", "Source", "Diff"; "Open in Code"; key hints "Enter" + "open in Code" and "Esc" + "close"; close button aria-label "Close the peek"; hint "Ctrl + click to peek"; diff caption "New file, not in HEAD"; stat "new file".
- The peek must never write `codeFileAtom`, `codeProjectAtom`, `codeViewModeAtom`, `codeHeadAtom` or any other Code-surface atom. Only Open in Code (through `openTarget`) touches the Code surface.
- Web links keep today's behavior: `WebLinksAddon` and its "Ctrl-click to open link" tooltip are unchanged.
- No jsdom render tests (repo convention). Logic is extracted to pure modules with tests beside them, and rendering is proven by the `code-peek` CDP scenario.
- Never hand-edit generated files. Run `task generate` after the Go type change.
