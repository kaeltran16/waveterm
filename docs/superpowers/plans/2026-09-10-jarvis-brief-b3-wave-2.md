# Jarvis Brief B3 Wave 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. This initiative explicitly stays inline: do not dispatch subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete B3 by adding the Vault Records split ledger, attached Brief asks, the Brief graph landing, and one-shot dossier/conversation restore.

**Architecture:** Reuse the existing dossier list/detail stores and RPCs for Vault; add only a thin pure records projection plus a Records renderer. Widen the stateless ask wire with attached orefs and move the Brief’s launch-local thread state into its store so contextual entry, graph actions, and restore all seed the same path. Keep all oref routing in `openref.ts`, and keep status mutation exclusively in the Brief peek.

**Tech Stack:** React 19, TypeScript, jotai, Vite, Tailwind 4, Vitest, Go, typed wshrpc generation, CDP scenario harness.

**Spec:** `docs/superpowers/specs/2026-09-09-jarvis-brief-meta-spec.md`

**Prototype:** `docs/prototype/jarvis-vault-records.html`

## Global Constraints

- Use the approved split-ledger layout: status-grouped searchable index left, selected record right.
- “History” means created/updated metadata plus the complete append-only decision log, including superseded/reverted entries; do not add raw Git revisions or a diff browser.
- Vault shows status read-only. The Brief peek remains the only B3 status-write surface.
- Vault Records must use `ListTaskDossiersCommand` and `GetDossierCommand`; add no new backend read command.
- Attached asks must pin the exact source orefs through `jarvisrecall.ScopeArgs.AttachedORefs`; do not create a second retrieval path.
- In Brief mode, Graph Peek must not render `Open run` until B5 gives runs a Stage-sheet destination.
- Reuse design tokens from `frontend/tailwindsetup.css`; no raw component colors, new token namespace, or new dependency.
- Keep pure view-model logic in `.ts` with colocated tests; keep `.tsx` renderers thin. Do not add jsdom snapshots.
- Do not hand-edit generated files. Run `task generate` after changing `CommandJarvisAskData`.
- Do not modify or stage the unrelated prototype files already staged by another session.
- Do not commit, push, or restart the live backend without separate explicit approval. Prepare one batched commit at the end.
- Do not dispatch subagents; the effort tracker explicitly records inline execution for B2 onward.
